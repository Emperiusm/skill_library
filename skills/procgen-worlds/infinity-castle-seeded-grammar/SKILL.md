# Infinity Castle: Seeded Grammar Worlds

## Purpose

This skill reconstructs the Infinity Castle streaming-grammar workflow, step by step, so another agent can build infinite procedural architecture the same way. Every phase has three parts: **Do** (the action), **Check** (how the human verifies it), and **Why** (the principle). The core method is: resolve every point in space by hashing coordinates + seed so there is no stored state; organize generation with an architectural grammar; merge each cell to ~2 draw calls with vertex-baked AO; synthesize the sound too.

## AAA studio practice

- **Generate, throw away, regenerate (Hello Games, *No Man's Sky*).** Sean Murray: "When you're standing here, what you see around you is generated around you. If you fly away, it's thrown away. If you fly back it's generated again. Everything will always be the same, though. It's a formula where the input is where you stand and the output is what you see. Since the input is the same, the output is the same"; "Effectively, our algorithms generate gigabytes of data on the fly when we enter a new solar system"; and the studio-discipline half: "Our artists build prototypes. They build silhouettes of creatures, effectively. Then we take those and morph them and texture them" ([GamesBeat, E3 2015](https://gamesbeat.com/how-no-mans-sky-creator-is-using-clever-tech-to-build-a-truly-indie-game-universe/)).
- **Generate from first principles, constrain with human logic (Frontier, *Elite: Dangerous* Stellar Forge).** "In *Elite: Dangerous*, when we are generating a system procedurally, each planetary system is formed from first principles. Bodies are gradually aggregated over a very long simulated time from available matter, taking into account its chemical composition" ([Engadget, 2014](https://www.engadget.com/2014-08-17-elite-dangerous-stellar-forge-tech-powers-planetary-creation.html)); David Braben: "I thought, 'Wait a second, I'll write a program to generate it'... 'We can just generate it every time – we don't need to store it'"; "you are constraining the rules to make things that make sense... applying a sort of 'human logic' to generating lots of galaxies" ([GamesBeat](https://gamesbeat.com/how-computing-legend-david-braben-schemed-to-create-elite-dangerous-and-raspberry-pi/)).
- **Rule graphs the artist can edit (Guerrilla, *Horizon Zero Dawn*, GDC 2017).** Jaap van Muijden, via 80 Level: "the procedural system assembles fully-fledged environments while the player walks through them, complete with sounds, effects, wildlife and game-play elements... from the graph editor where artists can define the procedural placement rules to the GPU algorithms that create a dense world around the player on the fly"; "every aspect of the world, although generated by a clever algorithm, could be easily modified by an artist. ## Phase 1: Hash the world

**Do**
1. "Each point in space is resolved by hashing coordinates + seed, so there's no stored state and it can stream in any direction."
2. Agent-executable: make determinism a tested property, not an assumption — a determinism gate that regenerates random cells at different times and asserts identical output hashes, catching any accidental state leakage in the "no stored state" design (Murray's formula: same input, same output).

**Check**
- Flying in any direction (including back) reproduces the same geometry: determinism from the hash, not from saved chunks.
- The determinism log shows the sampled cells, their generation timestamps, and matching hashes across regenerations.

**Why**
No stored state means no save/load, no chunk borders, no memory growth. Infinity is an addressing scheme, not a storage problem.

## Phase 2: Grammar, not noise

**Do**
1. "A grammar of chapters → districts → building plots → rooms keeps it from turning into noise soup."
2. "Every building is complete from foundation to roof ridge."
3. Agent-executable: farm variants from prototypes, Hello Games-style — author one architectural prototype per grammar level (building, room, district), then run an agent loop that mutates grammar parameters and generates N variants with a contact-sheet render for review; auto-reject on rule violations (collision, non-manifold merges). "Our artists build prototypes... Then we take those and morph them and texture them."
4. Agent-executable: expose the grammar (chapters → districts → plots → rooms) as editable, hot-reloadable rules, Guerrilla-style, and run an automated before/after render diff whenever a rule changes, so an agent can iterate the grammar without manually inspecting the whole world.
5. Agent-executable: validate each grammar level independently before descending, Stellar Forge/Dwarf Fortress-style — district connectivity checks before rooms generate; keep a per-stage seed record so any single cell reproduces in isolation for debugging.

**Check**
- Buildings read as complete structures (foundation to roof ridge), not noise fields: the grammar is the difference between procedural and random.
- The variant loop logs accepted/rejected variants with the violated rule named; the rule-diff shows exactly which visible cells changed on each grammar edit; per-stage seed records reproduce any reported cell.

**Why**
Raw noise makes terrain; grammar makes architecture. The chapter/district/plot/room hierarchy is what keeps a Demon Slayer–style castle from becoming "noise soup."

## Phase 3: Move districts as rigid bodies

**Do**
1. "Districts move as rigid bodies, and collision is computed in each district's local frame."

**Check**
- "You can graze a rotating tower at 40 m/s" — collision stays correct while the district moves.

**Why**
Local-frame collision is what makes moving architecture flyable: the world moves, the math doesn't.

## Phase 4: Budget the frame

**Do**
1. "Each cell merges down to ~2 draw calls with vertex-baked AO."
2. "New cells are built first along your flight direction."

**Check**
- The draw-call budget is per cell (~2), not per building: merging is the mechanism, the number is the contract.
- Generation priority follows the camera: what you fly toward exists first.

**Why**
A fixed per-cell draw-call budget is what makes "infinite" renderable: the frame cost is bounded by the visible cells, not the world size.

## Phase 5: Paint and sound at runtime

**Do**
1. Generate everything at runtime from the seed: "beams, shoji panels, lanterns, even the painted byōbu screens (painted into a texture atlas at runtime)."
2. Synthesize the audio: "a Karplus-Strong biwa, plus construction sounds that follow how fast cells are being generated."

**Check**
- The title's "no models, no textures" = no authored assets; textures are generated into the atlas at runtime (inference, confirmed by the author's own "painted into a texture atlas at runtime").
- Construction audio tracks the generation rate: the soundscape is coupled to the streaming system.

**Why**
If the world is generated, its paint and its sound should be generated too: authored assets would break the seed-determinism contract.

## The human method, distilled

1. No stored state (hash everything; stream any direction).
2. Grammar before noise (complete buildings, not soup).
3. Budget the frame (~2 draw calls per cell; build along the flight direction).
4. Collision in the mover's frame (districts as rigid bodies).
5. Sound follows the system (construction audio tracks generation rate).
