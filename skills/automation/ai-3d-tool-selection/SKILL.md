# Tool Selection for AI 3D Generators

## Purpose

This skill buys generators by method instead of by marketing: one
shared brief, scored honestly, retested once, with the durable value
placed on the method and the watch-outs rather than on any single
score. Every phase has three parts: **Do** (the action), **Check**
(how the human verifies it), and **Why** (the principle). The core
method is: same brief, scored comparison, second test, and a decision
based on the whole path.

## Tools used

Tools used: the compared tool set from the sources (Meshy, Tripo,
Rodin/Hyper3D, Sloyd, 3D AI Studio, Kaedim for image work), plus DCC
tools and engines for the import leg of the test. The set will age;
the method does not.

## Phase 1: Fix one shared brief

**Do**
1. Write one brief (for text) or one reference set (for image) and
   run it through every tool unchanged. For text, the brief must
   describe the whole form, style, and use. For image, the reference
   must be a strong three-quarter or multi-view set.
2. Do not tune prompts per tool in the first round. Tuning per tool
   measures your prompting, not the tools.

**Check**
- Is the brief identical across tools, recorded verbatim?
- If a tool needs a special prompt format, is that itself recorded as
  a usability finding?

**Why**
A comparison with different inputs is not a comparison. The shared
brief is what makes scores commensurable at all.

## Phase 2: Score 1 to 5 on the whole path

**Do**
1. Score each output 1 to 5 on: mesh usability (not preview beauty),
   topology cleanliness, material separation, scale correctness, and
   import behavior in the real destination.
2. Score the whole path, not the first mesh: generation, inspection,
   cleanup needed, texture separation, export, and import.
3. Record watch-outs per tool alongside scores: format limits, rig
   support, texture behavior, and licensing or export terms (free
   tiers commonly limit resolution, formats, commercial rights, and
   generations per month).

**Check**
- Are scores attached to the path, or only to the preview?
- Are watch-outs recorded even for the highest-scoring tool?

**Why**
Preview beauty is the most misleading axis in this market: the
prettiest first mesh often carries the most cleanup debt. Scoring the
path prices the work the team will actually do.

## Phase 3: Retest with a second prompt

**Do**
1. Retest the top tools with a second prompt (for text) or a
   character or environment piece (for image) that stresses a
   different weakness: organic forms, hard surfaces, or multi-part
   assemblies.
2. Promote only tools that hold up on both rounds. A tool that wins
   one brief and collapses on the second is a specialist, not a
   default.

**Check**
- Did the ranking survive the second round?
- If it changed, do you know which weakness the second brief exposed?

**Why**
One brief measures one strength. Production needs a tool that survives
variety, and the second round is the cheapest variety test available.

## Phase 4: Decide by job, then verify the import

**Do**
1. Decide by the asset's job first (concept speed, game shipping,
   product consistency, print), then by score within that job.
2. Before committing, import the winner's output into the real
   destination and estimate cleanup time. Free tiers are for
   evaluation; read licensing and export terms before relying on them
   for paid work.

**Check**
- Is the decision recorded as job first, score second?
- Has the winner's output survived a real import, not just a viewer?

**Why**
There is no single best tool, because the jobs differ more than the
tools do. A concept tool bought for production, or a production
platform bought for concepting, is money spent on the wrong strength.

## The human method, distilled

1. Same brief, every tool. Different inputs invalidate the comparison.
2. Score the path, not the preview.
3. Retest once with a different weakness stressed.
4. Scores age; the method and the watch-outs do not. Treat any
   published score as a dated test result.
5. Decide by job first, score second, import proof always.
